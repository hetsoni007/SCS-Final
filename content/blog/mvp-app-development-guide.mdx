## What counts as an MVP

A minimum viable product has three properties:

-   **It works.** Real users can complete the core action from start to finish.
-   **It is small.** It contains only what that core action needs.
-   **It teaches you something.** You can measure whether people use it and come back.

A clickable prototype is not an MVP, because nobody can really use it. A full-featured first release is not an MVP either, because it took too long to learn anything.

## The six steps

### 1. Validate the idea

Before any code, check that the problem is real and that people will change their behaviour to solve it. See [how to validate an app idea](/blog/validate-app-idea-before-building).

### 2. Scope the MVP

Write down the user, the core loop, the must-have features and, just as important, what is out of scope. Our guide to [scoping an app](/blog/how-to-scope-an-app) has a one-page template.

### 3. Choose the stack

For most MVPs: one shared codebase for iOS and Android, a managed backend, and bought-in services for auth, payments and push. See the [MVP tech stack guide](/blog/mvp-tech-stack-2026).

### 4. Design the core flow

Design the screens of the core loop first, with standard components. Polish onboarding and the main action. Leave the rest plain.

### 5. Build in short cycles

Working software every week or two, shown in a demo. This is where scope creep appears, so keep a "later" list and add to it freely.

### 6. Launch and measure

Release to a small group first, fix what breaks, then submit to the stores. Our [launch checklist](/blog/app-store-launch-checklist) covers submission. Decide in advance which number tells you the MVP worked.

## How long an MVP takes

Using the method behind our [app cost calculator](/app-cost-calculator/):

| MVP | Scope | Weeks |
|---|---|---|
| Lean | accounts, push notifications, managed backend | about 7 |
| With payments | the above plus payments | about 9 |
| With an AI feature | accounts, push notifications, one AI integration | about 10 |
| Funded MVP | accounts, payments, push, admin dashboard, custom API | about 15 |
| Funded MVP, custom design | the above with custom UI | about 18 |

Most MVPs we see land between 10 and 16 weeks once payments, an admin side and a custom backend are included. For more detail, see [how long it takes to build an app](/blog/how-long-to-build-an-app).

## What an MVP costs

With an indicative blended rate of $1,800 to $3,200 per week for a senior team:

| MVP | Indicative range |
|---|---|
| Lean | $13k to $22k |
| With payments | $16k to $29k |
| With an AI feature | $18k to $32k |
| Funded MVP | $27k to $48k |
| Funded MVP, custom design | $32k to $58k |

These are planning ranges, not quotes. A fixed price follows a short discovery call. For how each figure is built, see [how an app cost estimator works](/blog/app-cost-estimator).

## What to leave out of an MVP

-   A second user type, unless the product cannot work without it
-   Social features, feeds and chat, unless they are the core loop
-   Custom animation and bespoke illustration
-   Multiple languages
-   Advanced analytics dashboards
-   Anything described as "nice to have"

## Mistakes that sink MVPs

-   **Building for scale on day one.** Build cleanly and scale when the numbers demand it.
-   **Too many features.** Each one delays the moment you learn something.
-   **No success measure.** Without one, you cannot tell whether to continue.
-   **Skipping the admin side entirely.** Someone has to manage users and payments, even if the tool is basic.
-   **Treating launch as the finish.** The MVP is the start of [finding product-market fit](/blog/mvp-to-product-market-fit).

## Frequently asked questions

### What is MVP app development?

It is building the smallest working version of an app that lets real users complete its core action, so you can measure demand before investing in a full product.

### How long does it take to build an MVP app?

About 7 weeks for a lean MVP and 10 to 16 weeks for most MVPs that include payments, an admin side and a custom backend, depending on features and design.

### How much does an MVP app cost?

Using our method, roughly $13k to $22k for a lean MVP and $27k to $48k for a funded MVP with payments, an admin dashboard and a custom API. These are indicative ranges.

### What is the difference between a prototype and an MVP?

A prototype shows how the app would look or flow and cannot really be used. An MVP is working software that real users can use to complete the core action.

### Should an MVP be built for iOS and Android?

Usually yes, from one shared codebase, because the second platform adds little extra work. Launch on one platform first only if your users are clearly concentrated there.
